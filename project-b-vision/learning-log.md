## 진행 목표

## 진행 기록

### 1. 카메라 입력 환경 설정

- Python 가상환경에서 `opencv-python`을 설치하고 카메라 입력을 시도함.
- macOS 카메라 권한은 허용되어 있었고, Photo Booth에서도 내장 카메라가 정상 작동하는 것을 확인함.
- 최초 코드의 `cv2.VideoCapture(0)`은 장치 연결은 성공했지만 프레임 수신에 실패함.
- 카메라 인덱스 0~4를 순서대로 검사한 결과:
  - 인덱스 0: 연결 성공, 프레임 수신 실패
  - 인덱스 1: 연결 성공, 프레임 수신 성공 (영상 크기: 1080 × 1920)
  - 인덱스 2~4: 사용 가능한 장치 없음
- 최종적으로 `cv2.VideoCapture(1, cv2.CAP_AVFOUNDATION)`을 사용해 macOS 카메라 입력을 정상화함.

**배운 점:** `VideoCapture.isOpened()`가 True라고 해서 실제 영상 프레임까지 수신된다는 뜻은 아님. 장치 열기와 `read()`를 통한 프레임 수신을 각각 확인해야 함. 물리적 카메라 개수와 OpenCV에서 접근 가능한 장치 인덱스가 직관적으로 일치한다고 가정해서는 안 됨.

### 2. 파란색 영역 탐지 및 시각화

구현한 주요 처리 과정:

1. 카메라에서 프레임 읽기
2. BGR 영상을 HSV 색 공간으로 변환
3. `cv2.inRange()`로 지정한 파란색 HSV 범위([90, 80, 50]~[135, 255, 255])에 해당하는 픽셀을 마스크로 추출
4. Morphological Opening으로 작은 노이즈 제거
5. `cv2.findContours()`로 연결된 흰색 영역의 윤곽선 탐색
6. 윤곽선의 면적이 500보다 큰 경우 바운딩 박스와 중심점 표시
7. 원본 영상과 색상 마스크를 별도 창으로 출력

실행 결과:
- 원본 영상 창과 흑백 마스크 창이 함께 표시되는 것을 확인함.
- 마스크에서 파란색으로 인식된 영역은 흰색, 나머지는 검은색으로 나타남.
- q 키 입력을 통한 종료가 원활하지 않은 경우 영상 창에 포커스를 두어 입력을 받도록 하고, ESC 키도 종료 키로 추가함.

### 3. 실시간 움직임 안정성 확인

이후 중심점 보정과 최근 이동 경로 표시 기능을 추가한 버전을 실행해 다음 상황을 직접 확인함.

- 물체를 천천히 이동
- 물체를 빠르게 이동
- 물체를 화면 밖으로 숨겼다가 다시 보여주기
- 카메라와 물체 사이 거리 변경

**관찰 결과:** 위 상황들에서 사용자가 확인한 범위에서는 안정적으로 동작함.

추가된 개념:
- `deque(maxlen=30)`: 최근 중심점 30개만 보관해 이동 궤적을 그림.
- Exponential Moving Average 형태의 중심점 보정: `alpha = 0.3`으로 새 측정값과 이전 보정값을 혼합해 중심점의 급격한 흔들림을 완화함.
- 상태 표시: 물체 탐지 여부에 따라 Tracking / Searching을 표시함.
- `cv2.polylines()`: 저장한 중심점들을 선으로 연결해 이동 경로를 표시함.

### 4. 현재 확인한 한계와 질문

**문제 A: 배경의 파란 빛도 추적됨**
- 작업 환경의 뒤쪽에서 들어오는 파란 빛이 마스크에 포함되어 추적 대상이 되는 현상을 확인함.
- 원인: 현재 방식은 파란색 HSV 범위에 해당하는 픽셀을 모두 같은 기준으로 취급함. 파란색 물체와 파란색 조명을 의미적으로 구분하지 못함.

**문제 B: 파란색 물체가 두 개이면 하나만 추적됨**
- 원인: 현재 코드에서 `max(contours, key=cv2.contourArea)`를 사용해 면적이 가장 큰 윤곽선 하나만 선택함.
- 따라서 여러 파란색 영역이 존재해도 하나만 표시됨.

**문제 C: 동일한 물체의 정체성을 계속 유지하지 못함**
- 매 프레임 색상 영역을 새로 탐지하고 가장 큰 영역을 선택하므로, 이전 프레임의 대상과 현재 선택된 영역이 같은 물체인지 연결하지 않음.
- 따라서 현재의 경로는 특정 물체의 이동 이력이라고 보장할 수 없음.

## 질문을 통해 정리한 개념

### 왜 deque를 사용했는가?

`collections.deque`는 양쪽 끝에서 원소를 추가하거나 제거하는 데 효율적인 자료구조임. `deque(maxlen=30)`은 저장 용량을 30개로 제한하고, 새 원소가 추가되어 용량을 초과하면 가장 오래된 원소를 자동으로 제거함.

이번 프로젝트에서는 매 프레임마다 중심 좌표를 추가하면서 최근 30개 좌표만 유지해 이동 경로를 그리기 위해 사용함.

일반 `list`로도 구현할 수 있지만, `list.pop(0)`은 앞 원소를 삭제한 뒤 나머지 원소를 이동시켜야 함. 따라서 앞쪽에서 오래된 좌표가 계속 제거되는 제한된 기록에는 deque가 더 적합함. 다만 이 정도 데이터 크기에서는 list도 충분히 동작하며 deque가 필수인 것은 아님.

### 탐지와 추적의 차이

- 탐지(Detection): 현재 프레임에서 대상이 어디에 있는지 찾음.
- 추적(Tracking): 시간에 따라 동일한 대상이 어디로 이동하는지 연결하고 유지함.

현재 구현은 색상 기반 탐지와 중심점 시각화에 가깝고, 여러 후보 중 동일한 물체를 계속 식별하는 다중 객체 추적 기능은 아직 구현하지 않음.
