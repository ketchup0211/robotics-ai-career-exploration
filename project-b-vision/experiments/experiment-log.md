# Project B — Experiment Log

## Current Goal

Mac 내장 카메라와 OpenCV를 사용해 색상 기반 물체 탐지 및 추적을 구현하고, 실제 환경에서 발생하는 인식·추적 문제를 단계적으로 개선합니다.

## EXP-01. 카메라 입력 및 파란색 영역 탐지

### 구현
- OpenCV `VideoCapture`로 카메라 영상 입력
- BGR 영상을 HSV 색 공간으로 변환
- `cv2.inRange`로 파란색 범위의 픽셀을 이진 마스크로 추출
- Morphological Opening으로 작은 노이즈 제거
- `findContours`로 연결된 영역의 윤곽선 탐색
- 가장 큰 윤곽선을 선택해 bounding box와 중심점 표시

### 문제 해결: macOS 카메라 장치 인덱스
- `VideoCapture(0)`은 `isOpened() == True`였지만 `read()`에서 프레임 수신 실패
- `VideoCapture(1, cv2.CAP_AVFOUNDATION)`은 프레임 수신 성공
- 확인한 영상 크기: `(1080, 1920, 3)`
- 결론: 이 Mac 환경에서는 OpenCV 장치 인덱스 1에서 실제 영상 프레임을 받을 수 있었음
- 참고: 인덱스 0이 어떤 장치/스트림이었는지는 현재 로그만으로 확정하지 않음

## EXP-02. 중심점 안정화와 이동 경로 표시

### 구현
- 최근 중심점 최대 30개를 `collections.deque(maxlen=30)`에 저장
- Exponential Moving Average 방식으로 중심점 보정
- `alpha = 0.3` 적용
- 최근 중심점을 선으로 연결해 이동 궤적 표시
- 물체를 찾지 못하면 Searching 상태로 표시하고 경로 및 보정 상태 초기화

### 직접 실행해 확인한 결과

- 천천히 움직임
- 빠르게 움직임
- 화면 밖으로 숨겼다가 다시 보여줌
- 카메라와 물체 사이의 거리 변경

## 관찰한 한계와 새 질문

### 1. 배경의 파란 빛도 탐지됨
현재 구현은 파란색 HSV 범위에 들어오는 모든 픽셀을 대상으로 함. 따라서 파란색 물체와 파란색 조명/배경을 구분하지 못함.

### 2. 파란색 물체가 두 개여도 하나만 추적됨
현재 코드에서 `max(contours, key=cv2.contourArea)`로 가장 큰 윤곽선 하나만 선택하기 때문임.

### 3. 현재 구현은 물체의 정체성을 유지하는 추적이 아님
매 프레임마다 파란색 영역을 다시 찾고 가장 큰 영역을 선택함. 이전 프레임의 물체와 현재 프레임의 물체가 동일한지 연결하는 ID association은 아직 구현하지 않음.

## 학습 질문 및 이해한 내용

- **왜 deque를 사용했는가?**
  - 최근 N개의 중심점만 유지하는 고정 길이 큐가 필요함.
  - `deque(maxlen=30)`은 새 항목이 추가되면 오래된 항목을 자동으로 제거함.
  - 이동 경로에 필요한 최근 좌표만 보관하고 메모리 사용량을 제한할 수 있음.
- **왜 카메라 인덱스가 여러 개인가?**
  - OpenCV 인덱스는 물리적인 카메라 개수와 반드시 일치하지 않음.
  - 운영체제/백엔드가 노출하는 영상 입력 장치 인덱스이며, 실제 프레임 수신까지 확인해야 함.
- **왜 한 물체만 추적하도록 했는가?**
  - 최종 목표가 아니라 탐지와 프레임 간 객체 연결 문제를 단계적으로 학습하기 위한 초기 범위였음.
  - 다음 단계에서는 다중 객체 탐지와 객체별 ID 연결로 확장할 예정.
- **현재 코드가 움직임에 안정적으로 반응하는 이유는?**
  - HSV 기반 색상 분리, 작은 노이즈 제거, 윤곽선 기반 영역 계산, EMA 중심점 보정, 최근 좌표 궤적 표시를 조합했기 때문임.
