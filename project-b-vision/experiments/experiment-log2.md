## EXP-08: 사전 학습 YOLO의 실시간 객체 탐지 관찰

- **날짜:** 2026-11-05
- **상태:** 실행 및 초기 관찰 완료. 정량 평가 전.
- **목적:** 사전 학습된 YOLO 모델이 실제 카메라 영상에서 물체를 탐지하고 분류하는 모습을 확인한다.
- **환경 및 설정:**
  - 모델: `yolo11n.pt` (사전 학습 가중치)
  - 라이브러리: Ultralytics, PyTorch 2.14.1, OpenCV
  - 입력: Mac 내장 카메라, 기존 테스트에서 확인한 카메라 인덱스 1
  - 코드의 confidence threshold: 0.35
  - 코드에서 MPS 사용 가능 여부를 확인해 `device="mps"` 또는 `"cpu"`를 선택하도록 구성
- **직접 수행한 작업:** 실시간 YOLO 카메라 탐지 코드를 실행하고 파란 피크민 인형 및 종이 등을 카메라에 보여주었다.
- **관찰한 결과:**
  - 전반적으로 카메라 화면의 물체들이 탐지되는 모습을 확인했다.
  - 터미널에 `추론 장치: mps`가 출력됐다.
  - 파란 피크민 인형이 상황에 따라 `bird`, `banana`, `teddy bear` 등으로 분류됐다.
  - 종이가 바나나로 분류되는 오인식 사례도 관찰됐다.
- **해석 및 한계:**
  - 현재 사용한 사전 학습 모델은 COCO 데이터셋의 고정된 클래스 집합을 대상으로 한다. 피크민 인형이 해당 클래스에 없으면 모델이 그 이름을 직접 출력할 수 없고, 학습된 클래스 중 시각적으로 유사하다고 판단한 클래스를 출력할 수 있다.
  - 카메라 각도, 크기, 조명, 배경에 따라 이미지 특징이 달라지므로 같은 물체도 프레임마다 다른 클래스로 분류될 수 있다.
  - confidence는 모델의 예측 점수이며 실제 정답일 확률이 보정되어 보장된 값은 아니다. 높은 confidence만으로 정답이라고 단정할 수 없다.
  - `추론 장치: mps` 출력은 코드가 MPS를 선택했다는 뜻이다. 실제 연산 전체가 MPS에서 수행되었는지와 FPS는 별도 측정이 필요하다.
  - 아직 동일한 장면에서 반복 횟수, confidence, 거리, 각도 등을 통제한 비교 실험은 하지 않았다.
- **다음 단계:**
  1. 피크민 인형을 고정하고 정면/측면/거리/조명을 바꾸어 클래스와 confidence 변화를 관찰한다.
  2. 출력 클래스와 confidence를 프레임별로 기록해 분류가 얼마나 흔들리는지 확인한다.
  3. COCO 사전 학습 모델의 한계와 사용자 물체에 맞춘 커스텀 데이터셋 학습의 필요성을 비교한다.

## 개념 메모: YOLO 객체 탐지의 기본 원리

- YOLO는 이미지 또는 비디오 프레임에서 물체의 위치와 종류를 한 번의 신경망 추론 과정으로 예측하는 one-stage 객체 탐지 모델 계열이다.
- 일반적인 구조는 Backbone, Neck, Detection Head로 설명할 수 있다.
  - **Backbone:** 입력 이미지에서 가장자리, 질감, 형태 등의 시각적 특징을 여러 단계로 추출한다.
  - **Neck:** 서로 다른 해상도의 특징을 결합해 작은 물체와 큰 물체를 모두 탐지할 수 있도록 한다.
  - **Detection Head:** 각 위치에서 bounding box와 클래스별 점수를 예측한다.
- 최종 결과에는 bounding box 좌표, 클래스 ID/이름, confidence 점수가 포함된다.
- confidence threshold는 낮은 점수의 후보를 제외하는 기준이다. threshold를 높이면 일부 오탐이 줄 수 있지만 실제 물체도 놓칠 수 있다. threshold를 낮추면 더 많은 후보가 남지만 오탐이 늘 수 있다.
- confidence는 모델 내부 예측 점수이지, 현실에서 정답일 확률을 보장하는 값은 아니다.
- COCO 사전 학습 모델은 COCO의 정해진 클래스 집합에 속하는 객체를 인식하도록 학습됐다. 학습 클래스에 없는 물체를 반드시 '모름'으로 처리하는 open-set 인식 모델은 아니다. 따라서 학습된 클래스 중 하나로 잘못 분류할 수 있다.
- YOLO의 탐지(Detection)는 프레임별 물체 위치와 종류를 찾는 작업이다. 여러 프레임에서 동일 객체의 ID를 유지하는 Tracking은 별도의 연관 과정이 추가로 필요하다.
